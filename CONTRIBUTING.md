# Contributing to AgriRover

Thank you for your interest in contributing to the AgriRover project! We welcome contributions from everyone and are excited to collaborate with you.

## How to Contribute

### Reporting Bugs
- Check if the bug has already been reported in the [Issues](https://github.com/Aryan-git-byte/AgriRover/issues) section
- If it hasn't been reported, create a new issue with a clear title and detailed description
- Include steps to reproduce the bug and any relevant error messages or screenshots

### Suggesting Enhancements
- Use the [Issues](https://github.com/Aryan-git-byte/AgriRover/issues) section to suggest new features
- Provide a clear description of the enhancement and explain the motivation
- Include any relevant examples or use cases

### Submitting Changes

1. **Fork the repository** on GitHub
2. **Create a new branch** for your feature or bug fix:
   ```bash
   git checkout -b feature/your-feature-name
   ```
3. **Make your changes** and ensure they follow the project's coding standards
4. **Commit your changes** with clear, descriptive commit messages:
   ```bash
   git commit -m "Add description of changes"
   ```
5. **Push to your fork**:
   ```bash
   git push origin feature/your-feature-name
   ```
6. **Create a Pull Request** on the main repository with a clear title and description

## Code Standards

- Follow consistent naming conventions
- Write clear, self-documenting code
- Add comments for complex logic
- Include proper documentation for new features
- Test your changes before submitting a pull request

## Documentation

- Update relevant documentation files when making changes
- Add entries to the appropriate journal files if applicable
- Include images in `journal_images/` for visual documentation
- Ensure README files in each directory are kept up-to-date

## Project Structure

Please follow the established directory structure:
- **CAD designs** → `cad/`
- **Source code** → `src/`
- **Circuit designs** → `kicad/`
- **Assets** → `assets/`
- **Journal images** → `journal_images/`

## Communication

- Use clear and respectful language in all communications
- Be open to feedback and constructive criticism
- If you have questions, feel free to open an issue or discuss in pull request comments

## Recognition
